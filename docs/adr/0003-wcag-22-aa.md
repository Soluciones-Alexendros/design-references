# ADR-0003 — Objetivo WCAG 2.2 AA y modelo de contraste

- **Estado:** Accepted
- **Fecha:** 2026-11-10
- **Actualizado:** 2026-11-10 (Fase 2)

## Contexto

La spec SDD hablaba de WCAG 2.1 AA en varios puntos; el objetivo de flota es WCAG 2.2 AA (área táctil 2.5.8, etc.).

## Decisión

- Objetivo de accesibilidad: **WCAG 2.2 AA**.
- Contraste: pares en `tokens/contrast.pairs.json`; runner `test:contrast`.
- Umbrales efectivos = AA + margen configurable en el JSON (`margin.normal` ≥ **4.6**, `large`/`ui` ≥ **3.0**).
- `text.on-disabled` / `bg.disabled` marcado `exempt: true` → se reporta `EXEMPT`, no falla CI.
- Campo `apca` en el informe: **informativo**; no es gate de CI.
- Interactivos: `:focus-visible`, axe en light/dark; respetar `prefers-reduced-motion` y `forced-colors`.

## Alternativas

- WCAG AAA — fuera de alcance actual.
- APCA como gate — rechazado en F2 (solo columna informativa).
- Solo revisión manual — insuficiente para CI.

## Consecuencias

CI `a11y.yml` sigue siendo dueño de contrast + axe; no duplicar en `ci.yml`. Si un ratio falla el margen, se ajusta OKLCH — **nunca** se baja el umbral.
